# RAG 文档问答

## 项目定位

将分散的多格式文档变成可检索的问答上下文，让回答尽量贴近已有资料，并让检索质量可以被观察和评估。

适合展示的场景：

- 企业制度、流程和手册查询。
- 多份资料之间的信息整理。
- 需要保留资料来源边界的知识问答。

## 用户流程

1. 用户上传 `docx`、`pdf`、`txt`、`csv` 或 `md` 文件。
2. 系统识别文件类型，加载文本并按语义边界切分。
3. 用户选择知识库与模型参数，然后提出问题。
4. 系统进行混合检索、查询改写与相关性过滤。
5. 大模型根据检索上下文生成回答。
6. 评估模块使用 RAGAS 检查检索与回答质量。

## 技术栈

- **应用层**：Python、Gradio
- **编排层**：LangChain
- **检索层**：Chroma、Ollama `bge-m3`、BM25、EnsembleRetriever
- **上下文处理**：RePhraseQueryRetriever、LLMChainFilter
- **对话模型**：DeepSeek `deepseek-flash`，可切换 `deepseek-v4-pro`
- **评估**：RAGAS

## 设计重点

### 1. 混合检索

向量检索更擅长发现语义相关内容，BM25 更擅长命中明确关键词。两者组合可以减少单一检索方式的遗漏。

### 2. 先整理上下文，再生成回答

查询改写用于补足用户问题中的隐含信息；相关性过滤用于减少无关内容进入生成阶段。当前演示版本未接入独立重排模型，具体限制与后续验证方式见[安全与限制](security-and-limitations.md)。

### 3. 把评估纳入链路

RAGAS 把问题拆成上下文和回答两个层面：

- 上下文精度与召回率用于观察检索质量。
- 忠实度用于观察回答是否依据上下文。
- 答案相关性用于观察回答是否回应用户问题。

## 当前边界

- 评估需要带参考答案的测试集，不能只靠单次体验判断效果。
- 文档解析质量会影响切分与检索结果，复杂版式和扫描件仍需额外处理。
- 外部模型与嵌入服务会影响延迟、成本和可用性。
- 演示版本定位为单机实践，不是多租户企业知识平台。
