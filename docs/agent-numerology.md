# 命理 Agent

## 项目定位

把多个独立能力封装成工具，由 Agent 根据用户意图选择调用路径，并通过会话记忆支持多轮交流。

项目是 AI Agent 工具编排与 Web 服务实践，不把命理输出作为确定事实或现实决策建议。

## 用户流程

1. 用户在前端输入问题。
2. FastAPI 接收请求并创建或延续会话。
3. Agent 判断问题属于风水知识、八字、占卜、解梦还是普通搜索。
4. Agent 调用对应工具并读取结果。
5. 模型把工具结果整理成用户能理解的回答。
6. 会话历史写入 Redis，供后续轮次使用。

## 技术栈

- **后端**：Python、FastAPI、Uvicorn
- **前端**：Jinja2、HTML、CSS、JavaScript
- **Agent**：LangChain、OpenAI Tools Agent、AgentExecutor
- **知识库**：Chroma、Ollama `bge-m3`
- **对话模型**：DeepSeek `deepseek-flash`
- **会话**：Redis
- **部署**：Docker、Docker Compose

## 设计重点

### 1. 工具路由

提示词明确每种意图对应的工具，减少模型在多个能力之间随意选择。工具描述也会影响 Agent 的调用准确度。

### 2. 会话隔离

每次对话使用独立 `session_id`，Redis 保存历史并设置过期时间，避免不同用户共享上下文。

### 3. 失败兜底

外部接口、解析和模型调用都可能失败。系统需要对用户返回可理解的提示，同时把详细异常保留在受控日志中。

### 4. 部署可复现

Docker Compose 统一应用与 Redis 的运行方式，降低本机环境差异对演示的影响。

## 当前边界

- 外部服务依赖网络、配额和接口稳定性。
- 输入信息不足时，八字等工具无法可靠执行。
- Agent 的工具选择仍需用典型问题和异常输入持续评估。
- 生产部署需要补充密钥托管、限流、审计、监控和数据生命周期管理。
